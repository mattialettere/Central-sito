Encrypted chat: 6 questions before trusting an app

"End-to-end encrypted" has become an advertising slogan. These questions help you understand what an app really protects, and what it doesn't.

Download for iPhone Download for Android

Updated on 24 November 2026

In short: before calling a chat app private, ask: 1) is end-to-end encryption on for every chat? 2) What can the server see, i.e. which metadata? 3) Is there forward secrecy? 4) How do backups work? 5) Can the encryption code be checked? 6) How does the company make money? No app says "yes" to everything: what matters is that the answers are clear.

1. Is end-to-end encryption on for every chat?

With end-to-end encryption, messages are encrypted on the sender's phone and decrypted only on the recipient's phone: the server can't read them. The EFF guide "What should I know about encryption?" explains the difference from encryption in transit (HTTPS), which protects data on the way but leaves it readable to the server.

Some apps encrypt only certain chats end-to-end, or only if you turn on an option. Check that it also covers groups, photos, voice messages, files and backups.

2. What can the server see?

Even when the content is encrypted, the server usually knows who writes to whom, when, how often and how big the messages are. This is metadata, and it can say a lot: for example, that two people message each other every night. An honest app says which metadata it sees and how long it keeps it. Few apps manage to really reduce it, and those that do explain how in detail.

3. Is there forward secrecy?

Forward secrecy means that if someone steals a device key today, they can't read past messages they may have intercepted. The Signal protocol achieves it with the Double Ratchet, which derives new keys for every message so that earlier keys can't be calculated from later ones.

Not every app offers it. It is not a flaw to hide but something to know: without forward secrecy, protecting the device key becomes even more important.

4. How do backups work?

An unencrypted backup on a cloud service can undo end-to-end encryption: chats are protected in transit but readable in the backup copy. Ask whether the backup is encrypted, with which key and who knows it. If the key comes from a password or passphrase, it also matters how costly it is to guess by trial and error.

5. Can the encryption code be checked?

"Trust us" is not enough. When the code that encrypts messages is public, independent experts can review it. That doesn't make it automatically secure, but it makes the promises verifiable. Another good sign is public tests showing that the versions for different systems encrypt in the same way.

6. How does the company make money?

If an app is free and lives on advertising, it has a financial interest in knowing more about its users. Subscriptions, donations or paid business plans align interests better. Read the privacy policy: who processes the data, in which countries, and for how long.
